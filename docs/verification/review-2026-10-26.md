## 已修复问题

| 严重性 | 触发条件与原影响 | 修复与回归入口 |
| --- | --- | --- |
| P1 | 较新 `schema_version` 同时带有未知字段或改变字段类型；v1 反序列化先失败，配置被标成可写，保存可覆盖新版本原文 | `Config::parse` 先识别版本，保留完整 v1 诊断；`newer_schema_is_readonly_even_when_its_fields_are_unknown_to_this_version` 验证原文件及备份均未被改写 |
| P1 | Finished 状态、输出屏障和轮询重复触发 `remove`；第二次查找得到 `-1` 后可删除另一个标签，销毁其终端视图 | 对同一标签的删除请求加执行中保护、检查查找结果；`recovery.spec.ts` 验证只调用一次 forget 且保留另一标签 |
| P1 | 系统剪贴板读取尚未返回时切换/新建标签；返回文本按新的活动标签发送，可在错误 Shell 执行命令 | 固定发起操作的标签和视图，返回时再次核对；延迟剪贴板 E2E 验证没有向新会话发送内容 |
| P2 | forget 请求被拒绝后 `closing` 一直为真，关闭按钮禁用；restart 还会在删除失败后继续创建 | 失败时恢复可操作状态，仅在删除成功后重启；E2E 验证保留错误提示并允许明确重试 |
| P2 | 输出 Channel 首次失败后仍反复发送；失效视图的已发送数据占用全局预算，Finished 标签也可能长期持有租约 | 标记绑定失效、清空待显示队列、归还预算；两个生命周期测试覆盖运行中失败与结束后视图失效 |
| P2 | ACK 遇到临时拥塞即永久停止；后续输出无法归还窗口额度 | 合并最新前缀，对明确可恢复错误最多尝试三次，速率限制等待其一秒窗口；不可恢复时通知绑定所有者清理；测试覆盖恢复、次数上限及取消 |
| P2 | 输入正在等待 IPC，视图已销毁，随后收到可恢复错误；catch 将 stopped 改回 false | 异步返回及异常路径检查销毁状态，释放排队字节；回归验证队列不能复活，也不向已销毁界面报告错误 |
| P2 | 创建期间关闭会话，只有 Finished/OutputEnd 而没有 Running；已到达输出一直留在启动缓冲 | 结束阶段也允许解析只读尾部，输出异常/超时只完成一次并清理绑定；真实 xterm 浏览器测试覆盖跨通道先后顺序 |
| P2 | 设置页切换分类或重新加载时存在未保存草稿；后续操作静默覆盖草稿 | 统一草稿重置，丢弃前确认，保存期间禁用编辑/关闭；E2E 验证取消丢弃仍保留原草稿 |
| P2 | 磁盘配置改了会话上限后仅保存外观；完整配置被读入，但 Supervisor 仍使用旧限制 | 配置文件写入与运行时应用在同一写入锁内完成，两种保存入口复用相同路径；原生联调覆盖实际会话上限 |

| P3 | 重复应用外观配置即销毁并重建 WebGL；GPU 故障后重配会再次尝试相同失败上下文 | 活动终端/渲染模式不变时复用上下文，失效时保留 DOM 回退；测试验证上下文所有权和释放 |

## 剩余问题与验收边界

### P1：Windows 10 ConPTY 句柄增长仍未解决

两个既有断言仍失败：

- `backend::windows::tests::bare_conpty_creation_releases_its_handles`：裸 API 路径 4 次循环，句柄 **65 → 69**。
- `windows_contract::repeated_create_close_leaves_no_worker_growth`：完整会话 12 次循环，句柄 **71 → 83**；增长项为 `Process(unknown)`，其他记录的句柄类型数量不变。

另在隔离程序中复用相同公开 API，观察 4 次循环后的回收：句柄 **66 → 70**，100 ms、500 ms、1 s、5 s、10 s 和 30 s 均保持 70。日志和探针源码保存在 `target/review/conpty-probe.log` 与 `target/review/conpty-probe/`；该观察不能用短暂回收延迟解释。

裸 API 用例不经过 Supervisor、前端或配置层。现有证据将问题缩小到本机 ConPTY 调用/系统实现边界，但不足以确认具体 Windows 内部根因。本次没有关闭不属于应用显式持有的句柄，也没有放宽资源断言。此问题继续阻塞资源稳定性验收；代码回归不能声明全绿。
